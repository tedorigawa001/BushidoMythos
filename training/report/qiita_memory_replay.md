# 「睡眠中のリプレイ」で LLM の破滅的忘却を防ぐ — pilotで汎用PPL 59→752 が 59→135 に

## TL;DR

- 金融特化のファインチューニングで、自作モデルの**汎用言語能力が壊滅的に劣化**した（WikiText PPL 59 → 752、約12.7倍悪化）。これが **catastrophic forgetting（破滅的忘却）**。
- 脳科学の **補完学習系（CLS）/ 睡眠中のリプレイ**に着想を得て、学習中に**一般言語データ（WikiText）を少量インターリーブ**する「記憶リプレイ」を実装。
- **20% リプレイで忘却が約89%抑制**(PPL 59 → 135)。さらにスイープすると **5% だけで忘却の約71%を回収**(751→215)。
- しかも **held-out 金融はむしろ改善**(正則化効果)。「置換で学習が減る」点も **ADD モード**で解消できることを確認。
- 安価(データ混ぜるだけ)で強力な対策であることを pilot で確認した。スイートスポットは **5〜10%**。

:::note warn
研究用コードの実験ログです。投資助言ではありません。ローカル pilot のため絶対値は本番(A100)と異なります。
:::

---

## 背景：特化させると、汎用を忘れる

LLM を段階的に特化学習(general → 推論 → 金融 → SFT)させると、後半フェーズで**前に覚えた一般言語能力が崩れていく**。これは古くから知られる **catastrophic forgetting** で、自作の Recurrent-Depth Transformer(98.6M)でも実測していた：5フェーズ学習後、WikiText PPL が 54 → 361 に悪化していた。

脳はこれをどう防ぐか。**補完学習系仮説(McClelland et al.)**では、海馬が新しい経験を素早く覚え、**睡眠中にそれを新皮質へリプレイ**して、既存の知識と干渉しないよう統合する。ML 版が **rehearsal / interleaved learning** — 「古いデータを少量混ぜ続ける」だけ。

これを実装して効果を測った。

---

## 実装：一般言語アンカーのインターリーブ

学習スクリプトに `--replay_ratio` を追加。Phase 2 以降の各ステップで、確率 `replay_ratio` で**現フェーズのバッチを一般言語(WikiText-103)アンカーに差し替える**。

```python
# 学習ループ内（決定的・resume 安全な step シード RNG）
if replay_iter is not None:
    rng = random.Random(loop_seed * 2_654_435_761 + step)
    if rng.random() < replay_ratio:
        batch = next(replay_iter)   # WikiText アンカーに差し替え
```

ポイント:
- アンカーは「前フェーズ全混合」ではなく**一般言語のみ**(劣化を直撃する設計)。
- メモリ二重化を避けるため、Phase 1 で作った WikiText を再利用。
- 判定は step ベースで決定的(中断/再開しても再現)。

## 実験：replay 有無で汎用PPLを比較

公平な比較のため、各 run は **phase1_final(汎用学習済み)を再ロード**して**同一初期重み・同一シードで、replay_ratio だけを変えた**(厳密には replay ありは金融バッチの一部が置換されるので「金融更新量」も少し変わる）。

- phase1_final から **金融SFT(trading_qa)を 400 ステップ**学習(flat LR 1e-4)
- 学習後の **WikiText-103 PPL** を測定

### 結果

| 条件 | WikiText PPL | Δ(忘却) |
|---|---|---|
| baseline(学習前) | 59.28 | — |
| **replay 0%** | **751.87** | **+692.59** |
| **replay 20%** | **135.47** | **+76.19** |

- **replay なし**: 400ステップで汎用PPLが **59 → 752 に崩壊**(約12.7倍)。わずかな特化学習でも一般言語が壊れる。
- **replay 20%**: **59 → 135 に留まり、忘却Δを約89%削減**。
- 金融側の training loss は両 run とも順調に低下 → **少なくとも pilot では特化学習が阻害されていない**（金融タスク性能そのものの同等性は別途検証が必要）。

「20%だけ一般言語を混ぜる」という安価な介入で、忘却の大半を防げた。

---

## 追加実験：最適な replay 率と「置換 vs 追加」

上の 0%/20% は **GPU(Colab)でも再現**した(0%→約751、20%→約137)。さらに 5%/10% を加えてスイープし、**held-out 金融データ(financial_news、学習に未使用)での PPL** も同時に測った。

### スイープ：忘却 vs 学習のトレードオフ（置換モード）

| replay率 | 金融steps | WikiText↓（忘却） | finance↓（学習） |
|---|---|---|---|
| base（学習前） | — | 53.3 | 3572.9 |
| 0% | 400 | **751.4** | 865.5 |
| 5% | 380 | **215.5** | 774.6 |
| 10% | 360 | 147.9 | 771.4 |
| 20% | 320 | 136.5 | 816.0 |

- **忘却は replay で単調に改善**。しかも **5% だけで 751→215(忘却の約71%を回収)**。以降は逓減。
- **金融学習(held-out)は犠牲になっていない**。replay を増やすと金融ステップは減る(400→320)のに、held-out 金融 PPL はむしろ 0%(865)より 5-10%(775/771)が良い → **replay が正則化として働き、汎化を助けている**。
- スイートスポットは **5〜10%**。

### 置換 vs 追加（20% で比較）

「置換だと金融ステップが減る」点を切り分けるため、**金融ステップを 400 に保ったまま replay を追加**(総ステップを 500 に増やす = ADD モード)も試した。

| モード | total | 金融steps | WikiText↓ | finance↓ |
|---|---|---|---|---|
| REPLACE 20% | 400 | 320 | 136.5 | 816.0 |
| **ADD 20%**(計算+25%) | 500 | 400 | 145.2 | **742.3** |

- 忘却はほぼ同等(137 vs 145、どちらも 751 から激減)。
- **金融学習は ADD が明確に良い(742 vs 816)** ← 金融ステップを維持した効果。
- → 計算を払えるなら **ADD(金融ステップ維持 + replay 追加)が最良**。置換の唯一の弱点を解消できる。

### 推奨

| 狙い | 設定 |
|---|---|
| 最安・最大ROI | REPLACE 5%(忘却の71%を回収・ほぼ無償) |
| バランス | REPLACE 10%(忘却148・金融771) |
| 品質最優先 | ADD 10-20%(金融742+忘却145・計算+25%) |

## なぜ効くのか（脳科学の視点）

- **干渉の緩和**:新しい(金融)勾配だけで更新し続けると、一般言語を支える重みが上書きされる。リプレイは古い分布の勾配を混ぜ、その方向への過度な移動を抑える。
- **睡眠リプレイの ML 版**:海馬→新皮質のリプレイが記憶を「固定」するのと同じ構図。完全な再学習ではなく、少量の想起で十分。
- 証拠の強さ:CLS・rehearsal は神経科学でも ML(continual learning)でも実績が厚い領域。今回の大きな効果量(Δ 692→76)はそれと整合する。

---

## まだ言えないこと（pilot の限界）

- **部分評価**(40チャンク)なので絶対PPLは full と少し違う(baseline 59.28 vs full ≈ 54.86)。相対比較が要点。
- **flat LR + 400ステップ**は忘却を強めに出す設定。本番の5フェーズ(LR減衰あり)とは絶対量が異なる。
- 各条件 n=1・単一シード。ただし効果量が桁違いに大きく、方向性は明確。
- **「置換」であること**: replay は金融バッチを**差し替える**ため金融ステップが減るが、上の追加実験で **held-out 金融はむしろ改善**し、減らしたくなければ **ADD モード(金融ステップ維持+replay 追加、計算+25%)で解消**できることを確認した。
- 評価は held-out 金融(financial_news)PPL。**金融タスク性能そのものの直接評価**(指示追従や具体回答の質)は別途必要。
- 部分評価・短ステップ・n=1。スイープの絶対値は本番(フルフェーズ)と異なるが、**0%/20% は CPU/GPU で再現**しており傾向は堅い。
